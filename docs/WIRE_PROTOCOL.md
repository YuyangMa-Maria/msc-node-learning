# Communication Protocol

## Responsibility boundary

The VSN owns the online decision. The external receiver displays and records the
VSN result, so disconnecting the PC does not stop local sensing or fusion. MARH
participation is optional and is represented independently from whether the VSN
recommends assistance.

## Fast path: node summary

The ASN sends one packed `NodeSummaryV1` notification after each five-second
window. The 20-byte message contains:

| Field | Meaning |
|---|---|
| `node_id` | Stable source identifier |
| `modality` | Acoustic node type |
| `sequence` | Monotonic local observation sequence |
| `uptime_ms` | Sender-relative time |
| `risk_q15` | Calibrated local risk proxy in Q15 |
| `confidence_q15` | Entropy- and validity-adjusted confidence in Q15 |
| `status` | `normal`, `warning`, `critical`, `degraded`, `invalid`, or `low_power` |
| `model_version` | Active shared risk-head version |
| `crc16` | Message integrity check |

The VSN validates protocol version and CRC, acknowledges accepted summaries and
rejects stale data. It applies the quality gate before confidence-aware fusion.
When the ASN is unavailable, the VSN continues in `vsn_only` mode and reports
the missing node explicitly.

## Slow path: compatible model module

The runtime-swappable component is a 2,113-parameter shared higher risk head.
The private visual and acoustic encoders are never exchanged. Model transfer
uses control, data and status GATT characteristics with:

- transfer and model versions;
- direction and FP32/INT8 format;
- indexed MTU-sized chunks;
- CRC16 on control/status records and CRC32 on the complete payload;
- timeout, ordering, duplicate, replay and version checks;
- golden-vector execution validation before atomic activation;
- local rollback to the previous generation.

The VSN stores its next host-command transfer identifier in NVS before starting
a transaction. An ordinary VSN restart therefore advances the identifier rather
than causing a valid update to collide with the ASN's in-session replay guard.

Integrity checks detect accidental corruption; they are not authentication,
encryption or a cryptographic signature.

## External receiver protocol

VSN serial events start with `NLJSON ` and contain JSON schema version 1.

| Event | Purpose |
|---|---|
| `boot` | Camera, model and BLE initialisation state |
| `ble_state` | ASN connection, disconnection and recovery |
| `fusion` | Node scores/status, fused score/confidence, risk level/trend, alert, MARH state and model version |
| `node_output` | Per-node decision, source/transport, sequence and available stage latency |
| `sampling_state` | Automatic/manual mode and whether the ASN accepted the same mode |
| `marh_state` | Manual helper join or leave |
| `command_result` | Result of a host request or model transaction |

Each `fusion` event contains a deterministic warning generated by the VSN. The
warning includes `attention_required`, `severity`, `headline`, `evidence`,
`action`, `message`, and the original `triggered_mask`. `severity` is one of
`info`, `advisory`, `caution`, `high`, `critical`, or `unavailable`. An
`unavailable` warning means that no valid node evidence survived the quality
gate; it must not be interpreted as a low-risk observation. The receiver
displays and records this warning but does not rewrite it. `triggered_mask`
identifies nodes that crossed the trigger policy, whereas `evidence` lists the
valid node sources supporting the current fused decision; the latter can
therefore be non-empty even when no individual node crossed the threshold.

The PC may send newline-terminated ASCII commands:

```text
PING
STATUS
NODE STATUS
BLE RESCAN
SYSTEM RESTART
MODE AUTO
MODE MANUAL
SAMPLE VSN
SAMPLE ASN
SAMPLE BOTH
MARH JOIN
MARH LEAVE
MODEL PUSH
MODEL PULL
MODEL ROLLBACK
HELP
```

The dashboard's MARH update utility additionally uses `HOST MODEL BEGIN`,
`HOST MODEL CHUNK`, `HOST MODEL END` and `HOST MODEL PUSH`. These commands stage
a previously gated INT8 candidate on the VSN, validate it, activate it locally
and relay the same compatible head to the ASN.

`MODEL PUSH` transfers the validated VSN candidate head to the ASN. `MODEL PULL`
retrieves the validated ASN candidate and activates it on the VSN. These commands
exercise physical model-module exchange; they do not perform teacher training.
`BLE RESCAN` restarts discovery when the ASN is unavailable and is a diagnostic
and recovery action rather than an online fusion input.
`SYSTEM RESTART` restarts only the VSN representative node after acknowledging
the command, allowing a connected receiver to capture a reproducible cold-start
and BLE reconnection trace.

In manual mode, `SAMPLE VSN` captures one new camera frame and `SAMPLE ASN`
captures one new five-second microphone window. `SAMPLE BOTH` first requests a
fresh ASN window and triggers the VSN only after its BLE summary arrives. The
resulting fusion therefore uses the new acoustic and visual sequences. Returning
to automatic mode resets the VSN periodic deadline and resumes one-Hz operation
without catch-up inference bursts.

## MARH recommendation policy

The VSN may recommend helper intervention for `insufficient_evidence`,
`high_risk`, `rising_risk`, `node_loss`, or high-confidence
`node_disagreement`. A recommendation is a message, not an automatic takeover.
`MARH JOIN` is also legal while both nodes are healthy, matching the design in
which a helper may visit periodically.
